# Phase 3：ローカル版の起動（手順1〜5）

2026年10月28日（手順1〜3）・29日（手順4〜5）。[承認された計画](PHASE3_LOCAL_PLAN.md)に沿って、専用アプリからMacへ接続し、匿名認証・人工素材の撮影・仮審査と画像保存・写真入りTodayと詳細、切断・再試行・初期化までを実装した。実Firebaseの設定・課金先・配備は変更していない。

## 現在できること

- 「puzzle-sns ローカル」（`jp.puzzlesns.app.local`）をDebugビルドし、既存の開発版と別にインストールする。
- 非秘密のエミュレーター用ネイティブ設定を生成し、固定の`demo-puzzle-sns-local`でFirebase Coreを初期化する。
- ボタン操作でMacのFunctions Emulatorへ接続し、project・モード・応答形式・要求ごとのUUIDを確認する。接続エラーでは再試行できる。
- Auth・Firestore・Storage・Functionsを最初の要求より前にすべてMacへ接続し、Auth Emulatorで匿名認証する。App Checkは初期化しない。
- 中立的な年齢区分、内部検証の説明の確認、任意の署名を入力し、サーバーの日付と撮影セッションを取得する。16歳以上の申告と確認がない場合は開始できない。
- 通常終了・再起動ではMacのデータと端末の匿名認証・開始確認を引き継ぐ。
- 前面／背面カメラで人工素材を撮影し、正方形化・縮小・文章入力・撮り直し・最終確認を経てMacへ送る。仮合格時だけ既存サーバー処理がピースを確定する。
- 本人向けの盤面を購読し、参加者だけが取得できる画像を専用キャッシュへダウンロードする。Skiaで写真入りピースを表示し、拡大・移動・タップまたは「自分の写真の詳細」で署名・キャプションを見る。

接続確認用の`localHealth`だけが認証なしで動く。`getDayState`・`acceptLocalTest`・`beginCapture`・`getCapture`・`uploadCapture`・`submitCapture`・`syncBoardView`・`deleteOwnPhoto`・`reportPhoto`・`blockPhoto`は同じdemo projectの匿名認証と環境UUIDを必須とする。撮影は本人だけ、盤面は参加者だけが操作・取得できる。FIT・Galleryは今回のローカル画面には追加しない。Phase 3の後続として、本人の写真削除、通報・即時非表示、安全上のブロックを[Phase 4](PHASE4.md)で追加した。運営操作は未接続。

## 起動

Node 22.23.3・pnpm 10.34.6、JDK 21、Xcode、CocoaPodsを用意し、依存をインストールする。このMacでのPATHは[README](../README.md#開発環境)を参照する。JDKは起動時に検査する。iPhoneはDeveloper Modeを有効にしてMacを信頼し、USB接続してロックを解除する。Macと同じWi-Fiへ接続する。

リポジトリのルートでMacのプライベートIPv4を確認し、生成コマンドへ指定する。Wi-Fiのインターフェースが`en0`でない場合はシステム設定で確認する。

```sh
ipconfig getifaddr en0
pnpm local:prepare --host <MacのIPv4>
```

`.tools/local-runtime/mobile/`へ合成したネイティブ登録ファイル、`apps/mobile/local-runtime.local.json`へローカル設定を生成する。いずれもGit対象外。実アプリのGoogle登録ファイル・APIキー・サービスアカウントは使用しない。公開IP、URL、ポート付きhost、誤projectを拒否する。シミュレーターに限り`127.0.0.1`も指定できる。

ターミナル1でMacのAPIを起動し、そのまま維持する。

```sh
pnpm local:server
```

Authは19099、Firestoreは18080、Storageは19199、Functionsは15001でLANから接続する。Firestore WebSocketは19150。管理用hubは`127.0.0.1:14400`、loggingは`127.0.0.1:14500`、Functions Emulatorが内部起動するEventarc／Tasksはloopbackの19299／19499、UIは無効。既存のテスト用Emulatorとは別ポートを使う。使用済みポートがあれば停止し、他のプロセスを終了させない。既存のFirestore／Storage Rulesをそのまま読み込む。

終了はこのターミナルでCtrl+C。書き出しと終了が完了するまで待つ。Auth・Firestore・Storageを`.tools/local-runtime/data/`へ保存し、次の通常起動時に読み込む。dataや`server-identity.json`は手で書き換えない。突然の電源断・強制終了では最後の変更が保存されない可能性がある。

ターミナル2で接続端末の識別子を確認してビルドする。

```sh
xcrun devicectl list devices
pnpm local:mobile --device <iPhoneのIdentifier>
```

このコマンドは`APP_MODE=local`・`APP_ENV=development`でiOSプロジェクトを再生成し、Debug構成をビルド・インストールして、専用ポート8082のMetroを起動する。初回はAppleの開発用署名の選択や端末での信頼操作が必要になる。生成済み`ios/`は上書きされるため、通常版のネイティブ作業を並行しない。通常版へ戻る際も通常のAPP_MODEでprebuildし直す。

Androidでは、ビルド側のターミナルでSDK 36とJDK 17を指定し、`pnpm local:android --device <Androidの端末名>`を使う。端末へ入れずARM64ネイティブビルドだけを確認する場合は`pnpm local:android --build-only`。端末名・環境変数・確認結果・残作業は[Android起動手順](PHASE5_ANDROID_SETUP.md)を参照。MacのAPIを起動するターミナルでは引き続きJDK 21を使う。

アプリの「Macに接続して準備する」を押し、ローカルネットワーク許可が出たら許可する。年齢区分・内部検証の説明を確認し、「内部検証を始める」を押す。署名は空欄でもよい。準備後は「カメラを許可する」から撮影へ進む。MacのIPが変わった場合はprepareから再実行し、アプリのプロセスも再起動する。

紙に描いた丸・四角などの人工素材だけを使う。撮影後は任意のキャプションを入力し、「確認へ進む」→「この写真で投稿する」を押す。仮合格ではTodayに写真入りピースを表示する。その日の差替えはできない。撮影直後だけ短いピース化演出を行い、通常再起動では再生しない。「動きを減らす」設定にも従う。盤面を指で移動、二本指で拡大できる。署名とキャプションはピース詳細だけに表示し、詳細内にもローカル表示を維持する。

仮審査のシナリオを変える場合はサーバーを通常終了してから起動し直す。アプリからシナリオを送ることはできない。

```sh
pnpm local:server --scenario approved
pnpm local:server --scenario rejected
pnpm local:server --scenario held
pnpm local:server --scenario error-once
```

省略時は`approved`。`rejected`は未公開で再撮影、`held`は非公開の確認待ち、`error-once`は撮影セッションごとに一度だけ失敗し、同じ文章で再試行すると仮合格する。最初の失敗の印もMacに保存するため、Functionsのワーカー再起動で繰り返し失敗しない。既存の確定・保留済み状態はシナリオ変更で上書きしない。新しく撮影を試す場合は、後述の`local:reset`でローカル検証データを初期化する。

画像形式・5MiB上限・1024px正方形化・JPEG再エンコード・EXIF除去・所有者・日付・同日一枚・文章制限・連絡先チェックは実処理を使う。ローカル専用の禁止語は人工試験用の「内部検証禁止語」だけで、実運用ポリシーではない。Google Vision／Natural Languageはロードせず、画像内容の安全性は判定しない。正規化画像はdownload tokenなしで保存し、審査前の元画像は処理完了後に削除する。保留画像は非公開review領域へ置く。

既にローカル版をインストール済みで、ネイティブ設定を変えていない場合は、ビルドの代わりにMetroだけを起動できる。

```sh
APP_MODE=local APP_ENV=development pnpm --filter @puzzle-sns/mobile exec expo start --dev-client --port 8082 --lan --clear
```

接続できない場合は、同一LAN、Mac側の起動、iPhoneのローカルネットワーク権限、Macのファイアウォール、host設定を確認する。クラウドへの代替接続は行わない。インターネット到達性を開始条件にせず、Macとの疎通を使う。背景移行時は準備完了表示を隠し、復帰時はサーバーの状態を取得し直す。前面では30秒ごとにも日付を確認する。5秒間隔でMacのhealthと環境UUIDも確認し、通信失敗や初期化を検知すると写真・詳細を隠し、所有する画像バッチを破棄する。healthの応答待ちは最大8秒なので、Mac停止の検知には通常最大約13秒かかる。実際のOS通信停止のタイミングは実機確認と区別する。「接続をやり直す」では匿名認証と本人設定も再確認する。背景からの復帰にも同じ初期化確認を使う。監視は重複実行しない。

## ローカルデータの初期化

`local:server`を起動したまま、別のターミナルで実行する。対象はこの作業ディレクトリのローカル検証データすべてで、保存済み人工写真・匿名Auth・内部検証の開始確認・撮影・盤面も消える。通常の写真削除とは別の開発用操作である。

```sh
pnpm local:reset
# データを消して、別の仮審査で繰り返す場合
pnpm local:reset --scenario rejected
pnpm local:reset --scenario held
pnpm local:reset --scenario error-once
```

シナリオ省略時は現在のサーバー設定を引き継ぐ。サーバーを通常終了してから`local:server`で起動する場合の省略値は従来どおり`approved`。

初期化要求は`.tools/local-runtime/control.sock`（所有者だけが利用できるUnix socket）で受け付ける。LANへ初期化APIを公開しない。固定demo project・現在の環境UUIDを照合し、同時の初期化を拒否する。サーバー自身が起動したFirebase CLIだけを停止し、正常終了と保存完了後に`.tools/local-runtime/data`と`server-identity.json`を消す。設定・モバイル登録ファイル・他環境は対象外。シンボリックリンクや不正なパスを拒否する。終了に失敗した場合はデータを削除しない。

新しい環境UUIDで全Emulatorを再起動し、コマンドはhealthの応答確認まで待つ。サーバー停止中は初期化できないため、先に`local:server`を起動する。再起動が完了しない場合はサーバー側ターミナルを確認する。任意パス・project・PIDの指定は受け付けない。

iPhoneでは「接続をやり直す」、または背景から復帰すると、古い認証・開始確認・写真キャッシュを消して新しい内部検証に戻る。年齢区分と開始確認は本人がもう一度操作する。通常のサーバー再起動では環境UUIDと保存データを維持する。

## 通常版との分離

- Metroがアプリ入口をビルド時に選択する。通常版の画面は`src/cloud/`、ローカルの疎通画面は`src/local/`に置き、どちらも同時に取り込まない。ローカル画面は通常のsessionやFirebase通信実装を読み込まない。
- ネイティブのbundle/package ID・ローカル印・Debug判定を通信より前に検査する。通常バイナリやRelease、JSだけの切替では接続しない。MetroもローカルのRelease bundle生成を拒否する。
- 合成登録のprojectとpackageをprebuild前に照合し、実機ではFirebase Coreが読み込んだprojectも照合する。4サービスの接続先を設定してから通信する。App Checkを初期化せず、通常版の要求条件は変更しない。
- ローカルFunctionsは専用`index.local.ts`を別の`.tools/`内へビルドし、Emulator・demo project・専用mode・run UUIDのすべてを要求する。通常の`index.ts`やApp Check要求は変更しない。ローカル入口を通常のTypeScript出力からも除外し、root型検査と専用esbuildで検証する。
- Androidにも識別子とDebug用のネイティブ判定を用意したが、今回の実機対象はiPhoneのみ。ローカル設定に限りHTTPを許可する。

## 開始確認と保存の境界

ローカルの開始確認は`acceptLocalTest`でのみ受け付け、`local-test-v1`に固定する。既存CaptureServiceの確認形式をdemo内の`consents`で再利用するが、正式文書への同意ではない。通常版の利用文書版本は受け付けず、通常の`acceptOnboarding`はローカル入口から公開しない。日付・撮影セッション・同日制限・所有者の判定は既存のサーバー処理を使う。端末のUID・秘密情報は画面や返却DTOに表示しない。

端末では専用SecureStoreキーの`local-test-state`に本人の設定だけを保存する。ネイティブのインストール印・匿名主体・サーバー環境UUIDが一致する場合だけ復帰する。新しい環境では残存する認証・開始確認・撮影参照・ローカル画像キャッシュを消し、初期化が成功してから新しく匿名認証する。通常終了からの再起動では同じ環境UUIDを使う。初期化は下記のMacコマンドで行う。

各Callableは環境UUIDをデータの外側に要求し、サーバーの値と照合する。Macの環境を作り直したときに、古い端末状態のままでセッションを操作することを防ぐ。確認用応答のprotocolも2へ更新したため、古い画面は読み込み直す。

ローカル専用のCallable通信は、RNFirebase Authで取得した本人のIDトークンをHTTPのAuthorizationヘッダーへ明示して送る。[CallableのHTTP仕様](https://firebase.google.com/docs/functions/callable-reference)に従う。実機でFunctions SDKからの要求にAuthトークンが付かず、未認証で拒否されたための対応である。サーバーはCallableのトークン検証に加え、匿名認証・固定project・環境UUIDを引き続き検証する。認証情報はログへ出さない。通常版は既存のFunctions SDKを維持する。

盤面の購読はネイティブFirestore SDKで、本人の`clientState`と`views`文書だけを対象にする。キャッシュ由来のsnapshotは表示へ使わず、永続化も無効。画像はネイティブAuthのトークンをAuthorizationヘッダーに付け、固定のStorage Emulatorから[Expo FileSystemのダウンロードAPI](https://docs.expo.dev/versions/latest/sdk/filesystem/)で専用キャッシュへ取得する。公開URL・download tokenは使わない。実機でStorage SDKの`writeToFile`が`storage/unauthorized`となったためのローカル専用の対応であり、既存Storage Rulesによる参加者判定は維持する。通常版のStorage SDKは変更しない。

画像URIを渡す前にDTOと本人状態・環境UUIDを確認し、一部でもダウンロードに失敗した場合はバッチ全体を破棄する。20秒のタイムアウトと部分ファイルの掃除も行う。背景移行・購読エラーでは既存controllerが画像と詳細を消し、復帰時は再取得する。画像ファイルや他人の設定をSecureStoreへ保存しない。

## 自動検証

```sh
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm test:emulators
pnpm check:functions-artifact
pnpm check:local-boundaries
pnpm test:local
```

`test:local`はローカル専用ポートを使うため、継続起動中の`local:server`を先にCtrl+Cで終了する。独立して全Emulatorを起動・HTTP試験・保存・終了・再起動を行い、普段の保存データを読み書きしない。実Auth Emulatorトークンで開始確認・日付・撮影セッション・同時要求を通し、未認証・非匿名・別主体・不正なproject claim・誤環境UUID・開始確認前・直接書込みを拒否する。private Firestore文書・Storageへの不正な取得も確認する。保存・読込み後にはAuthのrefresh、開始確認済みの権限、同じ撮影セッションの復帰まで再検証する。試験用の保存物は専用verificationディレクトリに分け、成功後に消す。試験用Emulatorはloopbackだけで待ち受け、iPhoneから試験用環境へ誤接続しないようにする。

手順3ではさらに4種類の仮審査をそれぞれ独立起動で試験する。実トークンでのHTTPアップロード・確定、他人の送信拒否、クライアントによるシナリオ指定の拒否、壊れたJPEG・過大入力・文章制限・連絡先・人工禁止語、同時送信と確定の再試行、正規化画像の寸法・EXIF除去・tokenなし保存、審査元画像の削除、非参加者の画像取得拒否、保留画像の非公開を確認する。既存Emulator試験とローカルの継続起動・追加試験は同時に走らせず、順番に実行する。

手順4では参加者の`syncBoardView`とFirestore購読、非参加者のAPI・文書取得拒否をHTTP／実SDKの試験へ追加した。Emulatorの保存・再起動後には、承認済み盤面と認証付きで取得した画像のSHA-256一致も確認する。モバイル試験は、購読のcache無視と解除、非公開一時ファイルの破棄、取得失敗時の非表示、生成時だけの演出、復帰時の再取得、詳細と「動きを減らす」の扱いを対象とする。ジェスチャーとSkiaの実描画は実機確認と区別する。

手順5では、Mac停止相当の監視失敗・同一プロセスの再接続・背景中の遅い応答・初期化検知後の開始確認・拒否／保留／一時障害の画面を試験する。Unix socketの権限、不正project・任意パス・古いUUIDの拒否、別環境の保存データを変更しないことも確認する。`test:local`の最後には、専用`reset-verification`環境で実Emulatorの停止→Auth／Firestore／Storageの消去→UUID更新→再起動→シナリオ切替→通常再起動での維持までをHTTP経由で検証する。通常の保存データは使わず、成功後に専用ディレクトリを消す。4時をまたぐ承認・保留の公開拒否は既存のサーバー時計注入によるEmulator試験を維持する。

`check:local-boundaries`は通常Functionsの実ビルドとiOS／Androidの通常bundleのsource mapを調べ、ローカルモジュールの混入を検出する。CIにも追加済み。実機用Metroと同時には実行しない。今回、並列のbundle生成中にHMRのグラフ更新エラーが出たため、Metroを停止し、上記の`--clear`付き起動とアプリの再起動で読み込み直した。
