3文書は、承認済みのMVP仕様が完成した時点での利用者向け文案である。現在の開発版ですべての機能が使えるという説明ではない。未実装機能はレビュー事項に対応付け、各文書の冒頭にも未発効であることを記載した。

製品ルールの根拠は[PRODUCT_SPEC.md](../PRODUCT_SPEC.md)と[実装計画の承認記録D-01〜D-13](../IMPLEMENTATION_PLAN.md)。法令・ストア規約への適合や、専門家による確認が完了したことを示す文書ではない。`L-01`などのIDが付いた要確定の注記はレビュー事項に対応し、確定済みの運用やダミーの連絡先を意味しない。

## 次の作業

1. 運営者・問い合わせ先を決め、[レビュー事項](REVIEW_CHECKLIST.md)の未確定事項を埋める。年齢・権利許諾・保存・国外取扱い等は専門家へ確認する。
2. 実装・クラウド設定・運営手順と文面を照合する。通報、ブロック、削除、利用終了、審査・運営機能がない状態を、利用文書だけで補わない。
3. 利用対象に応じた文面のレビュー後、実際に読めるHTTPSページと文書セットの版本を用意する。URLの準備とアプリ接続は別作業とし、この初稿をそのまま同意対象にしない。
4. 接続時はモバイルの`legal.version`とFunctionsの`PUZZLE_LEGAL_VERSION`を一致させる。各URLが表示する版の内容を対応付け、旧版と改訂記録を保存する。草案IDを発効済み版本として設定しない。
5. 実機で全文の閲覧、未同意・年齢対象外での開始拒否、同意版本の記録・必要な再同意を確認する。外部利用前にはG-LEGAL・G-SAFETY等の既存ゲートを満たす。

今回はアプリコード、Firebase設定、公開サイト、利用文書URL、同意版本を変更しない。Apple／Google連携による復元をMVPへ追加せず、製品仕様の原本も変更しない。
