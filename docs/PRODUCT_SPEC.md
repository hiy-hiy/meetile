# 対面型パズルSNS プロダクト仕様書

バージョン：1.0  
更新日：2026年10月10日  
状態：実装前・承認待ち  
初期提供地域：日本  
対象年齢：16歳以上

## 1. プロダクトの目的

### 解決したいこと

既存SNSの多くは、すでに知っている人との交流か、アルゴリズムによる未知の人の推薦に偏っている。

本プロダクトは、現実の交友関係の延長上にいる「話したことのない同級生」「別クラスや他校の人」「友達の地元の友達」など、本来なら出会わなかったかもしれない人の存在を、対面での共同体験を通じて見せる。

ただし、アプリ内で関係を完成させることは目的にしない。相手の存在を知り、現実で話すためのきっかけだけを提供する。

### 一文コンセプト

> 会った人のピースだけが、偶然と不自由さを伴って一枚のアートにつながり、その先にいた人の存在が見える、対面起点の日替わりSNS。

### 設計原則

- 推薦ではなく、現実の対面から始まる
- 知らない人がオンライン上から突然介入しない
- 便利すぎる関係管理機能を持たない
- パズルの不自由さと偶然性を残す
- SNS内で関係を完結させない
- 人ではなく、その日に生まれたアートを記録する

## 2. 想定ユーザーと利用場面

### 主対象

- 日本国内の16歳以上の高校生
- 次の対象として大学生

### 主な利用場面

- 昼休みや放課後
- 部活動、委員会、文化祭
- 塾や習い事
- 他クラスとの合同授業
- 他校との大会やイベント
- 大学の授業、サークル、学園祭

### 期待する変化

- 話したことのない同級生へ声をかける
- 別クラスや他校に知り合いが増える
- 友達を介して、自分の交友関係の外側にいる人を知る
- 同じ人たちと過ごしても、毎日異なる共同作品が生まれる

マッチングアプリやランダムチャットにはしない。相手は必ず、現実の対面と既存の人間関係の連鎖を通じて現れる。

## 3. 一日の基本体験

### 3.1 日付の切り替わり

- 1日の境界は日本時間の午前4時
- 判定には端末時計を使わず、サーバー時刻を使う
- 日付キーは「日本時間のサーバー時刻を4時間戻した日付」とする
- 4時以降、前日の盤面は一切変更できない

### 3.2 最初の起動

その日の初回起動時は、まずピース用写真の作成を求める。

- TodayやFITなど、その日の機能は写真作成まで利用できない
- Settingsには移動できる
- カメラロールからの選択はできない
- 前面・背面カメラの両方を利用できる
- 撮影中の撮り直しは可能
- 写真確定前に任意のキャプションを入力できる
- 自動審査を通過すると、写真がピースになる演出を行う
- ピース化後は写真、キャプション、その日の署名を変更できない

審査で拒否された写真はピースになっていないため、再撮影できる。

### 3.3 日中

- 対面した相手とFITを試す
- 接続できない場合もある
- 他の人とのFITによって盤面が成長すると、最新の完成状態へ更新される
- 遠隔で盤面が更新された場合は、汎用的な通知を送る
- アプリを開いたときは再生演出を挟まず、最新状態を表示する

### 3.4 1日の終了

午前4時の状態を、その日の完成アートとして確定する。

- 同じパズルの全参加者に、同一の最終盤面を保存する
- ギャラリーから無期限に見返せる
- 後日のユーザー同士の紐付けや、「以前も一緒だった人」という表示は行わない

## 4. ピース生成ルール

### 4.1 基本構造

各ユーザーには、毎日1個のピースが与えられる。

ピースの四辺は、それぞれ独立して次のいずれかになる。

- 丸い凸
- 丸い凹
- 角ばった凸
- 角ばった凹

すべての辺が接続候補になる。四辺すべてが同じ種類になることも許可する。

### 4.2 噛み合わせ

接続可能な組み合わせは、形状と凹凸の両方が一致する場合だけである。

- 丸凸 ↔ 丸凹
- 角凸 ↔ 角凹

丸と角は接続できない。凸同士、凹同士も接続できない。

### 4.3 向き

- ピースと完成済み盤面は回転できない
- 生成された上下左右の向きを維持する
- ユーザーが移動・回転・再配置する操作は存在しない

形状はサーバー側でランダム生成し、写真確定前にはユーザーへ見せない。

## 5. パズル統合ルール

### 5.1 基本原則

各ユーザーが保有するのは、その時点の共有パズル全体である。

二人がFITするときは、本人同士のピースだけを接続するとは限らない。それぞれが保有する盤面同士を、任意の境界ピースで統合できる。

これにより、直接会っていない人でも、共有盤面のどこかが噛み合えば同じパズルへ入る。

### 5.2 接続候補の探索

盤面Aと盤面Bについて、向きを固定したまま、整数グリッド上のすべての相対位置を探索する。

候補が有効になる条件は次のすべてを満たすことである。

1. 両盤面の参加者が重複していない
2. 統合後の人数が20人以下
3. ピースの占有セルが重ならない
4. 新しく隣接するすべての辺が噛み合う
5. 両盤面の間に最低1辺の新しい接触がある

一部だけが噛み合っていても、別の接触箇所が不一致なら、その配置全体を無効とする。

### 5.3 配置決定

有効な配置のうち、両盤面間で新しく接する辺の数が最も多い配置を採用する。

最大接触数が同じ候補が複数ある場合はランダムに選ぶ。ただしサーバー処理の再試行で結果が変化しないよう、FITセッションIDと最新盤面の版番号から決定的な乱数seedを作る。

### 5.4 不成立

有効な配置が存在しない場合は接続しない。

- 盤面は変化しない
- FIT履歴は残さない
- 相手の盤面全体は開示しない
- 事前確認で表示された相手本人のピースだけは、その画面を離れるまで見えてよい
- どちらかの盤面が別のFITで変化した後、再試行できる

接続できないことは不具合ではなく、意図した不自由さである。

### 5.5 上限

- 1パズルは最大20ピース
- 参加人数を数値では表示しない
- 20ピースに達した盤面は「完成」となり、それ以上FITできない

## 6. 同期と同時FIT

盤面の正本はサーバーに置く。端末上の状態を正本にはしない。

複数のFITが同じ盤面へ同時に行われた場合は、

1. 先に確定したFITを反映する
2. 後のFITは、更新後の最新盤面を取得する
3. 最新盤面同士でもう一度、重複・人数・干渉・噛み合わせを判定する
4. 成立すれば接続し、成立しなければ失敗として返す

ユーザーが見ていた古いプレビューを、そのまま強制確定してはならない。

Firestoreトランザクションと盤面の版番号を使い、二重参加、盤面分裂、上書きを防止する。

## 7. 投稿と公開範囲

### 7.1 投稿の単位

独立した投稿やフィードは存在しない。写真は必ずパズルのピースとしてのみ表示される。

### 7.2 公開範囲

同じパズルに属する全員が、そのパズル内のすべてのピースを閲覧できる。

パズル外のユーザーは閲覧できない。

盤面が統合されるたび、両方の参加者全員へ新しいピースが見える。これが「友達の友達が段階的に見える」体験に相当する。

### 7.3 ピース詳細

ピースをタップすると、その写真だけを拡大表示する。

拡大時にのみ、次の情報を表示する。

- その日のユーザーネーム
- キャプション
- 通報・安全上のブロック操作
- 自分のピースの場合は写真削除操作

プロフィールや過去投稿へ移動する導線は存在しない。

## 8. 人間関係の扱い

| 概念 | アプリ内での扱い |
|---|---|
| 友達 | データとして存在しない |
| フレンド申請 | 存在しない |
| フォロー | 存在しない |
| 直接会った人 | FIT成立のため一時的に確認するが、関係履歴として保存・表示しない |
| 友達の友達 | 盤面統合によって間接的に同じパズルへ入った人として現れるが、ラベル付けしない |
| 同じパズルの人 | その日の写真を相互に見られる一時的な共同体 |
| 過去に一緒だった人 | 一切表示・紐付けしない |

誰が誰と直接FITしたかも表示しない。

## 9. 対面確認とFIT

### 9.1 開始条件

- 両者が同じ日の有効なピースを持っている
- 両者がFIT画面を開いている
- アプリが前面にある
- 端末同士が約10cm以内にある
- 周辺の候補が実質的に二人だけである

3台以上が近くにある場合は開始しない。ユーザーへ少し離れてやり直すよう案内する。

### 9.2 技術方式

- 全端末でBLEを利用
- 対応端末ではUWBを精度向上に利用
- iPhoneではCore Bluetooth＋Nearby Interaction
- AndroidではBLE Scan／Advertise＋Ranging API
- UWB非対応端末では、双方のBLE受信強度を一定時間確認して近接を推定
- GPSや位置履歴は利用しない

約10cmはUX上の目標であり、BLEだけで物理的な距離を厳密に保証するものではない。実機ごとの調整をリリース条件とする。

### 9.3 FITの流れ

1. 両者がFIT画面を開く
2. 端末が短時間だけ有効なランダムトークンを発信する
3. 双方が相手のトークンを検知したことをサーバーへ送る
4. サーバーが相互検知と日付、参加資格を確認する
5. 相手本人のその日のピースだけを表示する
6. 違う相手なら離脱できる
7. 両者が最終確認ボタンを押す
8. サーバーが最新盤面で接続判定を行う
9. 成功時のみ盤面を確定する

BLEトークンに写真、名前、安全IDを含めない。トークンは短時間で失効させ、再利用や遠隔送信を困難にする。

この方式は高度な中継攻撃を完全に防ぐ本人確認ではない。MVPでは、相互検知、双方確認、App Check、短い有効期限、回数制限を組み合わせる。

## 10. 4時をまたぐ処理

- 4時前に開始した撮影を4時以降に確定した場合、仮写真を破棄して新しい日の写真を撮り直す
- 4時前に開始したFITを4時以降に確定した場合、不成立にする
- FITセッションと撮影セッションは日付キーに固定する
- アプリ復帰時には必ずサーバーから現在の日付状態を再取得する
- Cloud Schedulerの遅延にかかわらず、各API自身が日付を検証する
- 4時の確定処理は、重複実行されても結果が変わらないようにする

## 11. ユーザーネームと識別子

### 11.1 ユーザーネーム

- 初回起動時に入力欄を表示する
- 空欄を許可する
- 重複を許可する
- 検索には使えない
- 本人確認には使えない
- 変更は次に作るピースから反映する
- 過去のピースは、その日に保存された署名を維持する

### 11.2 ユーザー向けアカウント

メールアドレス、電話番号、パスワードを使うユーザー向けアカウントは作らない。

### 11.3 内部識別子

運営上はFirebase Anonymous Authによる非公開の安全IDを持つ。

用途を次に限定する。

- アクセス権限
- 自分の写真削除
- 通報対応
- 利用停止
- 安全上のブロック
- 不正利用防止

検索、推薦、プロフィール、再会表示、行動分析には利用しない。

公開用の日次識別子は午前4時に破棄する。ギャラリー・削除・権限維持に必要な非公開情報は、別領域で保持する。

## 12. ギャラリー

- 日付ごとのパズルアートを一覧表示する
- 端末内へ保存し、オフラインでも閲覧できる
- 盤面を開いて各ピースをタップできる
- 全参加者に同一の最終盤面を保存する
- 成長途中の盤面も画像として書き出せる
- ギャラリー内の作品全体を個別削除する機能は設けない
- 保存期間は無期限

アプリ削除、機種変更、端末紛失時には、MVPでは復元できないことをオンボーディングとSettingsに明記する。

## 13. 書き出しと共有

現在の盤面と完成済み盤面は、端末へ保存・外部共有できる。

書き出し画像には、

- パズル領域外に小さくアプリ名
- 日付

を入れる。

次の情報は画像へ入れない。

- ユーザーネーム
- キャプション
- 内部識別子

アプリ内から単独ピースを書き出す機能は設けない。ただしスクリーンショットは防止できないため、利用規約と投稿前説明で二次保存・共有の可能性を明示する。

## 14. 写真削除

本人は、自分が撮影した写真を後から削除できる。

削除すると、

- 写真を全参加者の現在盤面とギャラリーから削除
- ユーザーネームとキャプションも削除
- ピースの形と配置は無地のまま残す
- 当日は本人のFITを無効化
- 当日の再撮影は不可
- 他の参加者による盤面の成長は継続可能

削除はサーバー上の画像、端末キャッシュ、検索可能なメタデータへ反映する。オフライン端末では、次回接続時に削除する。

すでに外部へ書き出された画像は回収できない。

## 15. 通知

MVPで実装する通知は次の3種類に限定する。

- 午前7時：その日の写真が未作成の場合のみ撮影を促す
- 12時〜13時：ピース作成済みでFIT可能な場合のみFITを促す
- 遠隔更新：別の人のFITによって自分の盤面が更新された場合

遠隔更新通知には、相手の名前や人数を含めない。

例：

> 今日のパズルが更新されました

完成済み、削除済み、必要な操作を終えたユーザーへ不要な通知を送らない。

## 17. 安全性とモデレーション

### 17.1 投稿前審査

写真：

- Google Cloud Vision SafeSearch
- 成人向け、性的示唆、暴力などを判定
- サーバーで画像を再エンコードし、EXIFを除去

テキスト：

- Google Cloud Natural Language `moderateText`
- 独自の禁止語チェック
- 電話番号、URL、SNSアカウントなどの連絡先掲載チェック

明確に危険な内容は公開しない。判断困難な内容は人の確認対象にする。しきい値と保留時のUXは実装前にテストデータで調整する。

### 17.2 通報

ピース詳細から通報できる。

通報後は、

1. 通報者の端末で即座に対象を無地表示
2. 運営の審査キューへ追加
3. 運営が画像、キャプション、関連する通報を確認
4. 必要に応じて全体削除・利用停止
5. 重大事案は定めた法的手順に従う

### 17.3 安全上のブロック

通常のSNS的なブロック一覧や関係管理は設けない。ただしストア規約対応として、非公開の安全ブロックを実装する。

- ブロックした組み合わせでは互いの写真、名前、キャプションを無地表示
- ブロック状態は相手へ通知しない
- 間接的に同じ盤面へ入ること自体は妨げない
- FITやパズルの履歴としては表示しない
- 安全IDを使って日をまたいで維持する
- 推薦や再会機能には転用しない

AppleとGoogleは、UGCアプリにフィルタリング、通報、迅速な対応、ユーザーブロックなどを求めている。[Apple App Review Guideline 1.2](https://developer.apple.com/app-store/review/guidelines/)・[Google Play UGC Policy](https://support.google.com/googleplay/android-developer/answer/9876937)

### 17.4 未成年者保護

- 日本限定
- 16歳以上
- Kidsカテゴリには出さない
- 年齢は中立的な文言で自己申告させる
- 児童の性的搾取、嫌がらせ、脅迫、違法行為を利用規約で明確に禁止する
- 通報窓口と児童安全担当の連絡先を用意する
- 外部ベータ前に重大事案・CSAM対応手順を文書化する

個人情報保護委員会の従来Q&Aでは、一般的に12〜15歳以下について法定代理人等の同意が必要になるとされている。また、2026年公布の改正個人情報保護法は、16歳未満の同意・通知等を法定代理人の対象とする規定と、本人の最善の利益を優先する責務を設けている。[個人情報保護法Q&A Q1-62](https://www.ppc.go.jp/files/pdf/250617_APPI_QA.pdf)・[2026年改正法概要](https://www.ppc.go.jp/files/pdf/260717_kaiseihounitsuite.pdf)

公開前に、日本法に詳しい専門家による利用規約、個人情報の取扱い、年齢確認方法、削除請求、重大事案対応の確認を必須とする。本仕様は法的助言そのものではない。

## 18. データ保存とプライバシー

### 18.1 写真処理

1. 端末上で縮小して通信量を抑える
2. 非公開の審査用Storageへ送る
3. サーバーで審査・再エンコード・メタデータ除去
4. 合格した正規化画像だけを本保存
5. 審査用元画像を削除
6. 参加者端末へ暗号化通信で配信
7. アプリ専用領域へキャッシュ

公開URLは発行しない。

Storage Security RulesからFirestore上の非公開参加者情報を参照し、そのピースを共有する安全IDだけに読み取りを許可する。[Firebase Storage Security Rules](https://firebase.google.com/docs/storage/security/rules-conditions)

### 18.2 保存方針

- 正規化写真と盤面：本人削除まで無期限
- 端末ギャラリー：無期限
- 審査用元画像：処理完了後に削除
- FIT用近接トークン：短時間で失効
- FITセッション：短期間でTTL削除
- 日次公開ID：午前4時に破棄
- 通報・利用停止記録：安全運用と法的義務に必要な期間
- 外部書き出し画像：アプリの管理外

詳細な保存期間表は、公開前の法務確認後にプライバシーポリシーへ記載する。

### 18.3 分析利用

Firebase Analyticsなどの行動追跡SDKは導入しない。

日単位で次の集計値だけを作る。

- ピース作成数
- FIT開始・確認・成功・失敗理由の件数
- 最終パズルサイズ分布
- 通報・削除件数
- OS／アプリバージョン別の障害件数

個人別行動履歴、日をまたぐ継続率、FIT相手の組み合わせ、位置履歴は分析しない。

## 24. 想定される例外と詰み状態

| 状況 | 挙動 |
|---|---|
| 通信できない | TodayとFITを停止し、Galleryのみ利用可能 |
| カメラ権限なし | 権限案内。ピースは作れない |
| Bluetooth権限なし | FIT不可。設定案内 |
| 通知権限なし | アプリは利用可能 |
| 写真審査で拒否 | ピース化せず再撮影 |
| 審査保留 | 公開せず結果待ち |
| 3台以上が近い | FITを開始しない |
| 相手が離脱 | セッション失効 |
| 相手が確認しない | タイムアウト |
| 同じ盤面の二人 | 接続不要として終了 |
| 参加者が重複 | 接続不可 |
| 20人を超える | 接続不可 |
| 有効配置なし | 何も変更せず終了 |
| 別のFITが先に確定 | 最新盤面で再判定 |
| 4時をまたいだ | セッション失効 |
| 自分の写真を削除 | 無地化し、当日のFIT停止 |
| 他人の写真が削除 | 次回同期時に無地化 |
| ブロック相手が同じ盤面に入る | 双方に無地表示 |
| 端末紛失・アプリ削除 | MVPではギャラリーと削除キーを復元できない |
| 20ピース完成 | その日は追加FIT不可 |
| 接続可能な相手がいない | その日の盤面のまま完成 |

接続不能や小さい盤面は失敗ではなく、日替わりアートの一部として扱う。

## 29. 現時点の最重要リスク

### 近接精度

BLEだけでは約10cmを厳密に保証できない。UWB非対応端末を含む実機検証で、誤接続率が許容範囲に収まることを確認する必要がある。

### 参加障壁

写真を作らなければその日の機能を使えず、FITも必ず成功するとは限らない。この不自由さはコンセプトの中心だが、離脱要因にもなる。

### モデレーション

高校生の写真を共有するため、投稿前審査だけでは不十分である。通報、ブロック、人による審査、連絡窓口、重大事案対応を実運用できなければ公開できない。

### アカウントを持たないこと

体験は軽くなる一方、端末紛失時の復元や本人確認が難しい。MVPでは復元不可を明示し、削除請求など法的に必要な問い合わせ経路を別途用意する。

### 接続成功率

単体ピース同士は少なくとも一辺が噛み合う確率が約68.4%だが、成長した盤面では形状と干渉の影響が複雑になる。実装前シミュレーションとベータ結果で検証する。ただし、任意配置や回転によって不自由さを取り除く変更は行わない。
