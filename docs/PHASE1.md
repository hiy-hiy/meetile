## 実装上の判断

境界で有効な盤面を検証し、各盤面を剛体として扱う。有効配置には最低1接触が必要なので、Aの空いている隣接セルとBの対応する境界セルから有限個の平行移動を生成できる。すべての新規接触が一致する配置だけを残す。穴を埋める接続も許可し、外接矩形による禁止や盤面の再配置を加えていない。

座標はxが右、yが下で、回転型・回転APIは設けない。参加者キーは幾何計算の内部入力であり、サーバーが非公開の所有者対応から用意する。クライアント用DTOではない。生成元や正しい所有者との対応をエンジン単独では保証できないため、Phase 2で入力の認可と正本取得を実装する。

同率選択の候補はx・y順で固定し、出力のピースとキーもロケールに依存しない順序に揃える。uint32 seedはサーバーから渡す境界とした。セッションID、正規順序の盤面ID、最新版本からseedを導出する処理はPhase 2で実装する。A／Bの引数順序もサーバー側で正規化する。エンジン自体は日時、セッション、有効期限、トランザクションを持たない。

`createSeededRandom`はMulberry32による再現用の非暗号学的PRNGである。開発の人工ピースと同率候補選択に使用し、認証・削除鍵・近接トークンへ使用しない。製品でのピース生成はサーバーが安全な乱数源を渡す。

座標を安全な整数として表現し、隣接座標・平行移動差分・加算がその範囲を超える入力を拒否する。20ピースの通常盤面では到達しない制限であり、不正入力で精度を失って統合することを防ぐ。

Phase 1のビルド形式はCommonJS＋宣言ファイル。Zod 4.6.5、TypeScript 5.9.3、Jest 30.5.2、ts-jest 29.4.14、fast-check 4.10.2、ESLint 10.12.0、typescript-eslint 8.71.1、Prettier 3.9.9を固定した。TypeScriptは検査ツールの対応範囲内の5.9を採用し、strictとisolatedModulesを有効にした。アプリ・Functionsの依存を追加していない。

本番の認可、安全状態、削除、審査、表示用データ分離は、実装計画のPhase 2以降の必須項目として残る。Phase 1の成功を外部ベータの許可として扱わない。

## ローカル検証結果

- `pnpm install --frozen-lockfile`：固定版の依存を再現。
- `pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm build`：成功。
- `pnpm test`と`pnpm test:coverage`：4スイート・67件成功。カバレッジは行99.62%、分岐90%、関数100%。CLIは別プロセス試験で検証し、集計対象から除外。
- `pnpm simulate --seed 42 --trials 100 --participants 20 --output artifacts/phase1`：2,375回のペア試行、1,897成功、478不成立。接触数分布は1辺1,733回、2辺149回、3辺13回、4辺2回。100試行中98試行で20ピースの一枚になった。
- 最初の試行のSVGをQuick Lookで描画して確認。丸／角、凸／凹が接続し、座標による配置が可視化される。SVGは人工色のみで、製品デザインの確定を意味しない。
- 1ピース同士の全256相手形状を列挙し、成功175通りを確認。理論値`1 - (3/4)^4 = 175/256`と一致。
- 最終差分を確認。AGENTS.mdとPRODUCT_SPEC.mdは変更せず、資格情報や実環境設定を追加していない。

`artifacts/`、`.tools/`、`dist/`、`coverage/`、`node_modules/`はGit対象外。シミュレーターの条件と方法はソースと本書から再現できる。
