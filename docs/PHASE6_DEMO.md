## 2. 実装

| 範囲           | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| サーバー       | `listGallery`（通常版・ローカル版）。呼び出した本人の、サーバー日付で前日以前の盤面だけを新しい順に返す。閲覧許可が有効・盤面が有効（統合で引退していない）・本人が参加者、の全条件を満たすものに限る。停止・終了した利用者は拒否。各盤面の最新表示（削除・ブロックの無地化）は既存の`syncBoardView`で作り直す                                                                                                                                   |
| 4時の確定      | 新しい定期処理は追加していない。各APIが日付を検証し4時以降は前日の盤面を変更できない既存の仕組み（§10）により、4時時点の盤面がそのまま最終盤面になる。全参加者は同じ盤面の正本から各自の表示を得る                                                                                                                                                                                                                                               |
| 端末保存       | `src/gallery/store.ts`。SQLite（`expo-sqlite`）に盤面表示、画像はアプリの書類フォルダへ保存（OSが消し得るキャッシュではない）。無地になったピースは画像を先に消してから表示を更新。画像取得に失敗しても無地化は反映し、既存の画像は残す。識別子が変わったら（ローカル初期化など）前の利用者のGalleryを消す。所有者キーは識別子のSHA-256                                                                                                          |
| 同期           | `src/gallery/controller.ts`。接続時（と日付が変わったとき、Galleryを開いたとき）に一覧→各盤面の同期→画像保存。端末で通報・ブロック済みのピースは保存前に隠す。オフラインでは保存済みを表示し、何も消さない                                                                                                                                                                                                                                       |
| 画面           | Today画面と未接続・オフライン画面に「Gallery」。日付一覧→盤面（既存の盤面表示でピースをタップして詳細）。アプリ削除・機種変更では復元できない旨を表示。作品ごとの削除機能は設けない                                                                                                                                                                                                                                                              |
| 書き出し・共有 | `src/export/board-image.ts`。表示中の盤面をSkiaで長辺2048pxのPNGに描き、OSの共有シートへ渡す（保存も共有シートから）。パズルの外の下側に小さく`puzzle-sns`と日付だけを入れ、署名・キャプション・内部識別子は描かない。無地のピースは写真を描かない。表示中の写真がそろうまでボタンを押せない。単独ピースの書き出しはない                                                                                                                         |
| 通知           | `src/notifications/`。端末内の予約通知だけ。朝7時（その日の写真が未作成のとき）と昼12時（ピース作成済み・20ピース未満・FIT可能なとき）。日付と状態が変わるたびに予約を作り直し、利用終了で消す。許可は利用者が「通知を受け取る」を押したときだけ求める                                                                                                                                                                                           |
| 利用終了       | 端末データの消去にGalleryのフォルダ（DBと画像）を含めた。DBを閉じてから消す                                                                                                                                                                                                                                                                                                                                                                      |
| ネイティブ部品 | `expo-sqlite`・`expo-sharing`・`expo-notifications`を追加。部品が入っていない古い開発版アプリでも既存機能が止まらないよう、端末に部品があるかを`src/native-available.ts`で確かめてから読み込む（当初の遅延読み込みだけでは、iPhoneの古いアプリで部品の初期化エラーが開発版のエラー画面として表示された）。iOSのプッシュ通知権限（aps-environment）は外した（`plugins/without-push-entitlement.cjs`）。遠隔プッシュは未承認の実クラウド接続のため |

ローカル版の画面（`src/local/`）だけに接続した。通常版（クラウド）の画面への接続は未実施。

## 3. 実装していないもの

- **遠隔更新の通知**：他の人のFITで自分の盤面が更新されたときの通知。アプリは安全のため背景で盤面の購読を止めるので、端末だけでは正しく実現できない。サーバーからのプッシュ（FCM／APNs）が必要で、実クラウド接続の承認と配備が前提。デモには3台以上も必要。
- 通常版（クラウド）画面へのGallery・書き出し・通知の接続。
- 通知の設定画面（現状はToday画面のボタンとOSの設定）。
- Gallery一覧のサムネイル。
- 長期未接続・容量不足・バックアップからの復元の検証。
- 公開用の日次識別子を4時に破棄する処理（D-05）。

- `pnpm check:local-boundaries`・`pnpm check:functions-artifact`：成功。
- Android 13実機（新しい部品入りのDebugビルド）：Today画面のボタン、書き出しPNG（1916×2048、下に`puzzle-sns`と`2026.10.30`、署名・キャプションなし）と共有シート、Galleryの一覧と盤面の写真、**未接続のまま再起動しての表示**、**サーバーで削除済みにしたピースが接続後に無地になり端末の画像ファイルも消える**ことを確認した。前日の盤面はローカル環境だけに一時的に作った人工データで、確認後にサーバーと端末から消した。

未確認：通知が実際に7時・12時に届くこと、共有シートからの端末保存、4時をまたいだ実際の確定。

## 5. 運用上の注意

- 最初のiOSビルドは、Macのディスク空きが約376MBしかなく失敗した（`errno=28`）。ユーザーの承認で今朝の不要なiOSビルド生成物（`.tools/phase5-ios-build`、6.5GB）を削除し、ユーザーがほかの容量も空けて空き16GBにしてからビルドし直した。ローカルサーバーの停止は、書き出し中の空き不足が原因だった可能性もある。**ビルドの前にディスクの空きを確認する**。

- 今回、ローカルサーバー本体が終了時の保存をしないまま止まり、Firestoreだけが残った（5-5dと同じ現象）。全体の書き出しを依頼した直後に終了操作を送っており、それが原因の可能性がある。Emulator試験との同時実行も以前から疑われている。18:36の全体の控えから同じ環境IDで復旧し、データは失っていない。**ローカルサーバーの稼働中はEmulator試験を動かさない。書き出しの完了を確かめてから終了する**。
- 明日の予選まで`local:reset`しない。4時を過ぎると今日（10月30日）の盤面がGalleryに入る。
